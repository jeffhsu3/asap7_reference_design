# Open-source SHA-256 baseline

This directory contains a reproducible SiliconCompiler 0.38.10 / OpenROAD
implementation of the SHA-256 RTL in `../sources/`. It uses SiliconCompiler's
`asap7_demo` target and the **stock LambdaPDK ASAP7** tech/cell libraries. It
is separate from the modified technology LEF and Cadence Innovus flow in this
repository; the extra density/color rules are **not** enforced here.

## Setup and run

From the repository root (with Yosys, OpenROAD and KLayout on `PATH`):

```sh
uv venv .venv
uv pip install --python .venv/bin/python 'siliconcompiler==0.38.10'
.venv/bin/python open_flow/run_sha256.py --check-only
.venv/bin/python open_flow/run_sha256.py --to synthesis  # quick RTL smoke test
.venv/bin/python open_flow/run_sha256.py                 # full P&R/GDS
```

The per-task timeout is 3600 seconds. Run the full flow in a durable terminal
or managed background process; a caller's foreground timeout can still kill it.
Outputs, logs and the generated manifest live in ignored `build/open_flow/`.
The GDS output is normally:
`build/open_flow/sha256/sha256_official/write.gds/0/outputs/sha256.gds.gz`.

The explicit timing mode uses the reference 600 ps clock period, 1 ps
input delay and 300 ps output delay at the typical library corner. The clock
port is excluded from input-delay assignment in `sha256.sdc`. These are example
constraints, not a verified tapeout target. This flow does **not** claim
signoff DRC/LVS, density compliance or timing closure.

The earlier successful baseline GDS was generated using the same stock ASAP7
target, before this script was re-created. Re-running can differ with tool and
package versions; verify reports and GDS before drawing comparisons.

## M6/M7 ring

The original Innovus script in `../scripts/innovus.tcl` creates an M6/M7 power
ring. `pdn_ring.tcl` replaces the stock LambdaPDK OpenROAD grid definition with
one that retains its followpin and strap layers, extends the M6/M7 straps to an
M6/M7 core ring, and connects adjacent PDN layers. The flow uses a 2 um
core-to-die margin so the ring fits inside the die. A complete local P&R run
through GDS export finished with zero task errors; the GDS passed `gzip -t`.
The PDN configuration report lists the ring on M6/M7, but the exported geometry
and via connectivity have not been independently inspected in the exported
layout, and signoff checks have not been run.

The default M2-to-M5 PDN connection keeps intermediate M3/M4 metal at minimum
width (`-min_width_layers {M3 M4}`), and the M5 straps use 0.024 um minimum
width rather than the stock 0.12 um. An isolated full run in
`build/pdn_m5_minwidth` used this configuration and passed OpenROAD's VDD/VSS
connectivity check and routed through GDS. A focused flat KLayout check found
zero `V2.M3.AUX.2` and zero `V4.M5.AUX.2` markers, compared to 2530 and 5060
before either width change. This is not evidence of complete DRC, sufficient
power-grid current capacity, or signoff connectivity in the exported GDS.

The M2-to-M5 connection also uses `-ongrid {M4}` to snap its intermediate M4
pads to LambdaPDK's stock M4 tracks (12 nm y origin, 48 nm pitch); other PDN
stripes and the M6/M7 ring are generated by this custom grid rather than by
LambdaPDK's default `pdngen.tcl`. In the isolated `build/pdn_m4_ongrid` run,
OpenROAD reported VDD/VSS connected, the exported GDS passed `gzip -t`, and
gdscheck's **unchanged** ASAP7 M4 deck reported zero `M4.AUX.1` and zero
`M4.AUX.2` markers, down from 7612 and 2211 in the min-width baseline.
The M4 deck still reported 61 `M4.S.4` and 153 `M4.S.5` markers. Neither
the full deck nor power integrity was cleared by this experiment.

The default M6/M7 ring now uses 0.224 um spacing and per-side core offsets
`{0.484 0.528 0.532 0.522}` (left, bottom, right, top) instead of uniform
0.5 um. These are specific to the present SHA-256 floorplan and 0.288 um ring
width: OpenROAD's ring command does not automatically snap ring shapes to
routing tracks. In the isolated full P&R run at `build/ring_ongrid_bottom_trial`,
the ring centres and edges in the floorplan DEF align to gdscheck's M6/M7
zero-origin grids and wide-wire tracks. The unchanged gdscheck M6/M7 decks
reported 0 findings on the exported GDS versus 31 on the earlier M4-aligned
baseline. OpenROAD reported VDD/VSS connected and zero final routing violations;
the GDS passed `gzip -t`. The stock M4 deck still reported 61 `M4.S.4` and
153 `M4.S.5` markers, with both M4 AUX counts at zero. These results do not
establish full-deck DRC, signoff connectivity, or power integrity. Recalculate
ring offsets if the core geometry, ring widths, or grid interpretation changes.

Post-route STA from the original ring run failed the 600 ps target: typical-corner setup WNS
was -661.10 ps, slow-corner setup WNS -1246.33 ps (reported Fmax 541.62 MHz),
and fast-corner hold WNS -4.06 ps. These results are not directly comparable
to the closed-source flow's modified PDK and Genus/Innovus implementation.
